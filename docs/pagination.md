# Pagination 전략

## Offset vs Cursor

* **Offset 기반 페이지네이션 (Page & Size)**
    * **방식**: `OFFSET`과 `LIMIT`을 사용하여 건너뛸 행(Row) 수를 지정해 데이터를 조회합니다. (예: `LIMIT 10 OFFSET 20`)
    * **장점**: 특정 페이지로 직접 이동(임의 접근, Jump)이 가능하며, Spring Data JPA의 기본 `Pageable` 인터페이스를 통해 직관적이고 빠르게 구현할 수 있습니다.
    * **단점**: 건너뛰는 데이터가 많아질수록 앞선 행들을 모두 읽고 버려야 하므로 성능이 저하되며, 조회 도중 데이터 추가/삭제 시 중복 노출이나 누락이 발생할 수 있습니다.

* **Cursor 기반 페이지네이션 (No-Offset)**
    * **방식**: 고유 식별자(PK, 타임스탬프 등)를 커서로 두고, 커서 기준 다음 데이터를 조회합니다. (예: `WHERE id < :lastId ORDER BY id DESC LIMIT 10`)
    * **장점**: 인덱스를 직접 탐색하므로 대용량 데이터에서도 일정한 조회 성능을 유지하며, 데이터 추가/삭제 시에도 페이지 꼬임이 없습니다.
    * **단점**: 이전/다음 탐색만 가능하여 특정 페이지 번호로의 임의 이동이 불가능하고, 정렬 조건이 복잡해질수록 쿼리 설계 난이도가 올라갑니다.

## Offset 방식을 선택한 이유

* **초기 MVP 규모에 충분한 성능**: 서비스 초기 단계의 데이터양에서는 Offset 연산으로 인한 성능 저하가 크지 않아 오버스펙을 방지할 수 있습니다.
* **기술적 비교를 위한 기준점 확보**: 우선 Offset 방식을 구현하여 기능 동작을 검증한 뒤, 향후 대용량 더미 데이터 환경에서 쿼리 병목을 직접 체감하고 Cursor 방식으로 리팩토링할 예정입니다.
