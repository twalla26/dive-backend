# 인증 방식

## **인증 방식 결정: JWT (JSON Web Token)**

Dive 서비스에서는 **JWT 기반의 무상태(Stateless) 인증 방식**을 채택했습니다.

### **1. 도입 배경 및 선정 이유**

- **MSA 확장성 확보**
  - 현재는 모놀리식 아키텍처이지만, 향후 MSA 환경으로의 확장을 고려했습니다.
  - 세션 방식은 서버나 중앙 저장소(Redis 등)에 상태를 저장하므로, 서비스가 분단될 경우 모든 요청마다 세션 저장소를 조회하는 I/O 병목이 발생합니다.
- **자체 완결적 검증 (Self-Contained Verification)**
  - JWT는 데이터(Payload)와 서명(Signature)을 자체 포함합니다.
  - 각 마이크로서비스는 중앙 인증 서버를 거치지 않고, 비밀키를 이용해 개별적으로 서명만 검증함으로써 독립적이고 빠른 인증 처리가 가능합니다.

### **2. 한계점 극복 전략 (보완책)**

- **토큰 탈취 및 상태 제어 문제**
  - 이미 발급된 JWT는 서버 측에서 임의로 만료시키기 어렵다는 단점이 있습니다.
- **Access Token 짧은 주기 + Redis 블랙리스트 적용**
  - 이를 보완하기 위해 Access Token의 유효기간을 짧게 가져가고, 로그아웃이나 탈취 신고 시 해당 토큰을 **Redis 블랙리스트**에 등록합니다.
  - 저장소 메모리 오버헤드를 최소화하기 위해 토큰의 남은 만료 시간만큼만 TTL을 설정하여 자동으로 삭제되도록 관리합니다.
